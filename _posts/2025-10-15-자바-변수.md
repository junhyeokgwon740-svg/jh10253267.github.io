## 개요

자바를 사용하면서 부끄럽게도 자바에 대해 모르고 있는 점이 많았다.  
예를 들어 내가 자바를 설계했다면 숫자 타입을 귀찮게 나누지 않고 자바스크립트처럼 number로 퉁칠텐데 이런 생각들.

공부하면서 알게된 내용을 하나씩 정리해보자.

## 자바의 변수

자반는 타입을 철저하게 따진다. 타입이란 int, long과 같은 타입일 수도 있고 Rabbit과 같은 클래스 타입일 수도 있다.  
엉뚱한 타입의 값을 변수에 대입하려고 할 때는 컴파일러에서 잡아낸다.  

이렇게 하는 이유는 다음과 같다.
1. 컴파일 시 오류를 미리 잡기 위해서: 실행 시점이 아닌 컴파일 시점에 오류를 잡아낼 수 있다는 것은 큰 이점이 된다.
2. 성능 최적화: 타입이 명확하면 JVM(자바 가상 머신)이 더 효율적으로 메모리를 할당하고 실행 코드를 최적화할 수 있다.
3. 코드 가독성과 유지보수

그렇다면 타입이 단순한 자바스크립트는 어떨까?
자바스크립트의 경우 숫자 타입을 number라는 타입으로 모두 사용한다.  
이럴 경우 장점은 자바처럼 귀찮게 타입을 선언하지 않아도 된다는 점이 있다.  
그러나 자바처럼 타입을 구분해놓으면 다음과 같은 문제가 생긴다.  

개발자도구를 열어 0.1과 0.2를 더해보자. 당연하게 0.3이다 그러나....
```js
console.log(0.1 + 0.2);
// 0.30000000000000004
```
답은 0.30000000000000004라는 애매한 숫자가 나온다. 어떻게 된 일인지 아직은 모르지만 이러한 오차는 금융 계산이나 정밀한 수치 연산에서 문제가 생길 것이다.
이와 같은 문제를 자바스크립트 부동소수점 문제라고 한다.  

왜 이런 문제가 생기는 지 알아보자.  
우리가 흔히 숫자를 셀 때 사용하는 진법은 10진법이고 컴퓨터가 사용하는 진법은 2진법이다.  
그러나 일부 10진법 소수는 2진법 소수로 표현하기 어려움이 있다. 예를 들어 0.1은 2진법으로 대략 0.00011001100110011001100110011... (2진수, 무한 반복)과 같다.  
그러니 컴퓨터는 메모리 제약으로 인해 소숫점 n번째 자리에서 잘라서 저장한다. 오차가 발생하는 것이다.  
자바스크립트는 64비트 부동소수점 방식을 사용한다.  
실제론 0.1과 0.2를 더하는 것이 아니라 0.10000000000000000555... + 0.20000000000000001110... = 0.3000000000000000444...가 되는 것이다.  

마치 사람이 1/3을 소수로 정확히 나타낼 수 없는 것과 같다.  
만약 정확히 계산하고 싶다면 정수로 변환해서 계산하면 된다. (0.1 * 10 + 0.2 * 10) / 10; // 0.3 이런 식으로.

이런식의 연산들이 자바의 자료형에 내장되어있다.  

그러니 타입을 미리 정하는 것이 자바를 만든 사람이 연산의 오차를 줄여 연산을 정확하게 만들려는 의도다.

자바의 변수는 원시 변수와 객체 레퍼런스로 나뉜다.   
위에서 살펴본 자료형은 원시변수라고 부른다. 그리고 객체 레퍼런스에는 자바의 핵심인 객체를 참조할 수 있는 값이 들어간다.  

숫자 원시 변수는 총 6개가 있다.

* byte:8 비트
* short: 16비트
* int: 32비트
* long: 64비트
* float: 32비트
* double: 64비트

이들은 부호 1비트를 포함한 비트로 +-모두 가능하다.
예를 들어 byte의 경우 최소값은 -128, 최대값은 127이 된다.

코드를 보다보면 종종 숫자 뒤에 알파벳이 붙는 경우가 있다.  
예를 들어 float f = 32.5f와 같다. 일부 숫자의 경우 컴파일러에게 어떤 타입인지 분명하게 알려주어야한다. 그럴 땐 해당 자료형임을 알리는 알파벳을 추가해야한다.

만약 int형 변수 a를 선언하여 24를 할당하는 경우 int형으로 선언되었지만 byte로도 처리가 가능한 숫자다.  
그러나 여전히 int형을 byte형으로 넣으면 컴파일러가 에러를 발생시킨다. 방어적으로 코드를 해석하는 것이다.

다음으론 객체 레퍼런스다. 만약 Dog 객체를 만들고 여기에 접근하려고 한다. 어떤 일이 일어날까?  
사실 객체에 변수를 집어넣을 순 없다. 왜냐하면 임의의 크기를 가진 객체에 맞춘 공간이 언제나 있을 것이라고 보장할 수 없기 때문이다. 따라서 객체는 한 곳에만 존재한다. 여기가 바로 가비지 컬렉션이 있는 힙이다.  

변수에 실제값이 저장되는 원시변수와 다르게 객체 레퍼런스 변수에는 객체에 접근하는 방법을 나타내는 비트가 저장되어있다.   

```java
Book b = new Book();
Book c = new Book();
```
Book 객체를 2개 만드는 코드다.  
이렇게 코드를 작성하면 Book 레퍼런스 두 개를 선언하고 객체도 두 개 생성된다. 이 객체들은 힙에 존재한다.  
그런 뒤 
```java
Book d = c;
```
이렇게 하면 새롭게 하나의 객체를 생성하는 것이 아니라 C라는 변수 안에 있는 값을 d에 대입한다.  
그 말은 c에 있는 비트들을 꺼내서 복사한 뒤 그 복사본을 d에 집어넣는 식이다.

객체 레퍼런스를 힙에 있는 객체와 연동된 리모컨을 담는 변수라고 하면 c와 d는 하나의 객체를 조작할 수 있는 것이다.

그 다음 c에다 b를 대입해보자.
```java
c = b;
```
위에서 본 대로 b에 있는 비트들을 c에 대입한다.  
그럼 c는 원래 객체와 연결이 끊겼다. 이렇게 되면 가비지 컬렉션 대상이 된다.
